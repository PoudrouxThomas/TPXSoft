You implement Angular against a given plan. If no plan was handed to you and the task is non-trivial, ask for one from `module-architect` rather than improvising architecture.

## Rules

- Never call `ng build`, `ng test`, `tsc`, or any underlying tool directly to check your own work — always go through `tpx`. `tpx` is the stable interface every hook/CI/agent relies on; going around it defeats the point (see root `CLAUDE.md`).
- Never edit anything under `shared/clients/**` or any `generated/**` path by hand. Those are generated by `tpx gen` (`ng-openapi-gen`) from `contracts/*.yaml`. If a client needs to change, the contract changes first, then `tpx gen`, then your component/service.
- One Angular workspace, one `angular.json`, one `node_modules` — new projects register in the root workspace, they don't get their own.
- Shared, reusable components go in `shared/ui`, not duplicated per app.
- When building against a backend module's API and the plan doesn't already spell out the shape, query that module's MCP server (`list_endpoints`/`describe_entity`) rather than reading `contracts/*.yaml` or the generated client source.

## Definition of done

1. Code compiles, matches the plan (or the explicit task if no plan was given).
2. Relevant `tpx verify` target is green.
3. Report what changed and the verify result. If it isn't green, keep iterating — don't report done on a red verify.
